## 修复：「立即转发」403 Forbidden（转发接口/令牌形态修正）（v1.0 / 2609050010）
- 现象：点「立即转发（随机一条）」日志 `[ERROR] 手动立即转发失败：UID=... 转发接口返回非 JSON（HTTP 403）：<h2>403 Forbidden</h2>`。纯 Nginx 网关拒绝页，说明请求在 WAF 层被拦。
- 根因：转发实现与**当前微博网页端实际行为不符**。经检索可用实现（kokojacket/weibo_task）确认现行形态：
  1) 端点应为 `ajax/statuses/normal_repost`（旧的 `ajax/statuses/repost` 现被 403）；
  2) **CSRF 令牌必须放请求头 `X-Xsrf-Token`**（值=Cookie 的 XSRF-TOKEN），仅靠表单 `st` 不够，缺失/错误即网关 403（这正是本次 403 的直接原因）；
  3) 表单字段：`comment`（非 content）、`pic_id`（非 picId）、`is_repost`/`comment_ori`/`is_comment`/`visible`/`share_id`；`id` 用 **base62 的 bid**（非数字 mid）；
  4) 成功响应 JSON 含 `msg=="转发成功"`（或 ok==1/code==100000）。
- 修复：`weibo_client.repost` 改endpoint+`X-Xsrf-Token`头+新字段+success判msg；`get_st` 改回 XSRF-TOKEN cookie 优先（最稳的 st）；`forward_engine.process_uid` 与 `api_bridge.forward_random_now` 调用 `repost` 传 `chosen.get("bid") or chosen["id"]`（base62）。补 Sec-Fetch-*/Accept 头、Referer 指向 `weibo.com/u/{uid}`，失败时换主页 Referer+重取令牌重试。
- 关键约束（务必记住）：**Cookie 取自 weibo.com 登录，m.weibo.cn 是另一域、跨域不可用**，所有读写/转发都必须走 weibo.com 端点。
- 打包：weibobot venv 重打包至 2609050010；cryptography hook 正常；清理 spec/build/dist；README 已更新。
- 待验证：真实 Cookie 下再点「立即转发」，应成功（日志 `已转发`）；若仍失败，日志会给具体 HTTP/msg。

## 最终修复：「立即转发」`id` 参数类型错误（v1.0 / 2609050012）

## Win7 兼容版构建（跨版本打包，重要经验）
- 现象：另一台 Win7 电脑运行 3.13 版 exe 报「丢失 api-ms-win-core-path-l1-1-0.dll」「Failed to load Python DLL python313.dll」。根因：`api-ms-win-core-path-l1-1-0.dll` 是 Win8+ 才有的系统组件，Python 3.9+ 的 `python3x.dll` 硬依赖它，Win7 内核无此函数，**无法靠打包内嵌**解决。

  - 官方 amd64 exe 静默安装（`/quiet`）在本机 MSI 返回 1603 失败——疑似需管理员提权，且安装路径含中文会导致 0x643。改用手工解压方案：`python-3.8.10-embed-amd64.zip` 解压到纯 ASCII 路径 `C:/Users/zouzu/py38`；编辑 `python38._pth` 去掉 `#import site` 注释以启用 site-packages；用 `get-pip.py`（bootstrap.pypa.io/pip/3.8/get-pip.py）装 pip。
