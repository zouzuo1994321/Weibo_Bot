# 2026-09-06 工作日志

## 标题栏回退为系统原生（撤销 v1.0.1 自定义 JS 拖动方案）（内部 2609060002）
- 用户反馈：v1.0.1 的 JS 受控拖动（`bindTitleDrag` + 后端 `window_move`）在 pywebview edgechromium 下"故障更严重了"，要求把顶部栏恢复到 2609050016 的状态。
- 关键事实：2609050016 早于自定义无边框标题栏（该栏在 2609050018 才引入），当时用的是**系统原生标题栏**（`frameless=False`，无自定义 `#titlebar`、无三圆点）。所以"恢复到 2609050016 的标题栏"= 恢复原生标题栏。
- 用户选择"仅标题栏改回原生"（保留 2609050017 之后的所有功能，包括 Bug2 概览每秒刷新 / Bug3 图片稳健下载）。
- 改动：`app.py` `frameless=True` → `frameless=False`；`ui/index.html` 删除自定义 `<header id="titlebar">` 三圆点栏；`ui/app.js` 删除 `let DRAG`、`bindTitleDrag()` 调用及其函数、以及 `windowMinimize/windowToggleMaximize/windowClose` 函数（这些仅服务于自定义无边框栏）。`refreshOverviewLive` 的 setInterval 保留。
- 验证：`node --check ui/app.js` 通过；`py_compile app.py` 通过；build.py 用 weibobot venv 重打包至 2609060002（v1.0.1）。
- 备份：build.py 自动把上一版 2609060001 归档到 `history/微博bot小助手_2609060001.exe`，可随时恢复。清理根目录残留 `.spec`。README 版本迭代记录表首行追加 2609060002 一行（说明标题栏回退原生）。
- 结论：窗口拖动现在由系统原生标题栏负责，主体区域文本可自由选中/复制，彻底消除"拖动 vs 选词"冲突；且不损失任何后续功能。
